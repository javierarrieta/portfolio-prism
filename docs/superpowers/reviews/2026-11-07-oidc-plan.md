### Rejected (with evidence)

| Finding | Why rejected |
|---|---|
| comprehension (nit): "`ROCKET_SECRET_KEY=$(openssl rand -base64 32)` is described as 256-bit but Rocket private cookies need a 64-byte key" | Rocket 0.5.1 `config/secret_key.rs:218` accepts **44 or 88 base64 characters, or 64 hex**, and then `derive_from` for anything ≥ 32 decoded bytes (`< 32` is rejected). `openssl rand -base64 32` yields exactly 44 characters decoding to 32 bytes, which is the documented 256-bit form. The plan now states the accepted lengths and the source line so the next reader can check it. |
| structural (nit): "heading hierarchy is clean; no fix" | No action required; recorded as a pass. |
| structural (nit): "apply spec §9's `Accept` branch to `/auth/login` is an unregistered extension" | Kept deliberately and now stated as such in Task 6: discovery can fail at `/auth/login`, and a browser should not receive bare JSON. Narrowing it to the callback alone would leave the more common failure mode unstyled. |
