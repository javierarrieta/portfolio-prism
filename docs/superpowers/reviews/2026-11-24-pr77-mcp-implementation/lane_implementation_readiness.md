## Refutations and accepted risk

- **Audit predicate vs migration predicate: identical.** `audit_asset_symbols.sh:59-75` (`group by portfolio_id, upper(symbol)` … `where n > 1`) vs `0006_asset_symbol_unique.sql:44-52` (`GROUP BY portfolio_id, upper(symbol) HAVING count(*) > 1`); same `string_agg` spellings/ids, same ordering. The only theoretical divergence — a NULL `upper(symbol)` group being flagged by both but not constrained by a unique index — is impossible: `assets.symbol TEXT NOT NULL` (`migrations/0001_init.sql:52`). The body's "runs the identical predicate" claim holds.
- **`openapi.json` / `api.d.ts` are consistent with the code.** 23 path keys counted in `docs/openapi/openapi.json` (lines 12-1228), including `/api/staged-batches*` (1005-1107) and `/api/tokens*` (1108-1196); mirrored in `frontend/src/types/api.d.ts:95-133`. Money fields are `"type": "string"` on the write schema (`openapi.json:2476-2477`), matching `strict_decimal_json`. CI enforces both artifacts: the `--print-openapi` diff step and `generate-types` + `git diff --exit-code frontend/src/types/api.d.ts`. `/mcp` absent by design (`agent/mount.rs:31-38`, `tests/route_coverage_test.rs:223`).
- **All eleven documented gates do run in CI.** `AGENTS.md`'s eleven: migrate, `prepare --check`, `cargo test`, `check_access_gate.sh`, `check_pricing_seam.sh`, `check_backup_portability.sh`, `check_upload_path.sh`, `check_migrations.sh`, `check_sqlx_cache.sh`, `clippy` — all ten are steps in `build-and-test`; the eleventh, `cargo build --release`, is the `release-build` job. The six gates the body names are all present. `check_migrations.sh:265-297` pins `uq_assets_portfolio_symbol` to `(portfolio_id, upper(symbol))` and column order, so the "fails with the index dropped" claim is pinned.
- **No new secrets or env vars are actually required.** The only `env::var` reads in `src/` are `DATABASE_URL`, `ALLOWED_ORIGINS`, `BACKUP_ALLOW_PRICE_RESTORE`, `YAHOO_BASE_URL`, `EODHD_API_KEY` and `auth/mod.rs`. PAT secrets are SHA-256 over 43 base62 chars (~256 bits) with no pepper (`auth/pat.rs:14-16,127-130`, `migrations/0003_api_token.sql:8-10`), so nothing new must be provisioned. Token minting is a session-authenticated UI flow (`api_routes/tokens.rs`, `App.tsx:71,806`), which the body does describe.
- **The frontend-first window is survivable.** `AccessTokensPanel.tsx:85,95,106` catch a failed `/api/tokens` list and render "Could not load tokens." rather than crashing, so new-frontend + old-backend degrades to an error message on two panes, not a broken app.
- **Accepted risk, correctly declared by the body:** CI cannot detect `0006` collisions (its database is empty), and `0005`/`0006` are non-`CONCURRENTLY` on the stated `replicas: 1` + `Recreate` shape. Both are documented at the mechanism (`0005`, `0006:100-112`).
